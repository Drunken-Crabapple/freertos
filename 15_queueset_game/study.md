# 第37集：队列集——改进程序框架（思路）

## 为什么改框架

- 驱动只上报设备原始数据，任务负责把数据转换为应用指令。遥控器从控制游戏改为控制音量，只改任务中的用途转换，不改驱动的按键解析。
- 每个设备单独建立处理任务，会增加任务栈和任务控制块的内存开销；改用一个 `InputTask` 统一处理多个设备队列。

## 轮询与阻塞

- 轮询多个队列且每次不等待：有数据就处理，没有就检查下一个；全部为空时，若循环没有阻塞或延时，会空转占用 CPU。
- 阻塞等待红外队列时，编码器队列来数据不能解除这次等待。设为无限等待可能一直无法处理后续队列；设为10个 tick仍会延迟处理其他队列，只是改成周期性轮询。
- 队列集让一个任务同时等待多个成员队列：全部没数据时可以阻塞，任意一个成员队列成功写入数据都能唤醒等待任务。
- 唤醒是恢复就绪，获得 CPU 后才继续执行；选出有数据的成员队列后，还需要从该队列接收数据。

## 队列集存什么

- 队列集本身也是队列，保存成员队列的句柄通知；实际数据仍保存在各成员队列中。
- 成员队列成功写入一条普通队列数据时，FreeRTOS 自动向队列集加入对应句柄，不需要应用手动发送句柄。
- 同一个句柄可以出现多次。依次向A、B、A各发送一条数据，队列集依次记录A、B、A。
- 队列集容量按成员队列容量之和设置：A最多2条、B最多3条，队列集需要5个通知位置，不是只按两个队列设为2。
- 从队列集取得A的句柄，只取走一个通知，数据A1仍在A中；还要读取A，才取出真正的数据。

```text
队列A：[A1][A2]      队列B：[B1]
队列集：[A句柄][B句柄][A句柄]

等待队列集 → 取得成员句柄 → 读取对应队列 → 处理数据 → 再次等待
```

## 本工程结构

```text
红外驱动 ──→ 红外队列 ───┐
                         ├→ 队列集通知 → InputTask → 挡球板队列
编码器驱动 → 编码器队列 ─┘
```

- 顺序：创建成员队列 → 创建队列集 → 将成员加入队列集 → 运行输入任务。
- 新增设备时，为它准备原始数据队列并加入队列集，在输入任务中增加对应处理，不必为每个设备新增任务。
- 本工程实际使用 `xQueueCreateSet()`、`xQueueAddToSet()` 和 `xQueueSelectFromSet()`；具体接口编程属于下一集。
